# Gemini 3.7 代支持

- **Date:** 2026-08-13
- **Type:** feature
- **Scope:** `gemini3_7`, `gemini3_6`, `auto_client`, `registry`, `tests`
- **PR:** [#168](https://github.com/Prism-Shadow/agenthub/pull/168)

[English](2026-08-13-gemini-3.7.md)

AgentHub 现已在官方 Gemini API 和 Vertex AI 上支持 `gemini-3.7-flash`，即 Google 最新的稳定版 Flash 模型。

## 协议发现

- 两轮实况抓取（先是带思考的流式工具调用，再用工具结果和原始 thought signature 进行重放）确认其线路协议与 Gemini 3.6 代完全一致：采样参数仍处于弃用状态（实况探测显示 `temperature` 依然被忽略），仍不允许对模型回合做预填充，thought signature 原样重放，思考通过 `thinking_level` 枚举配置。
- 唯一在模型层面可见的变化：`gemini-3.7-flash` 只接受 `low`、`medium` 和 `high` 三个思考档位。对 `minimal` 的实况探测返回 HTTP 400 "Thinking level MINIMAL is not supported for this model"。

## 实现

- 由于协议完全一致，共享的客户端目录按最新一代重命名，正如 `claude5/` 服务于 Claude 4.7 至 5：`gemini3_6/` 更名为 `gemini3_7/`（`Gemini3_6Client` → `Gemini3_7Client`），两种语言均是如此，并继续服务 `gemini-3.6-flash` 和 `gemini-3.5-flash-lite`。路由将 `gemini-3.7` 置于 `gemini-3.6` 和 `gemini-3.5-flash-lite` 别名之前，这些别名仍受支持。
- 客户端现在按模型钳制思考档位，所用机制与 Gemini 3 客户端在 2026-07-24 变更中获得的相同：在 `gemini-3.7-*` 模型上受支持的集合为 `low`/`medium`/`high`，因此 `ThinkingLevel.NONE`（映射为 Gemini 的 `minimal`）降级为 `low`；3.6 代模型保留完整的四档集合，不受影响。
- 按最新版本规则，`gemini-3.7-flash` 在受环境变量控制的 E2E 模型列表（官方与 Vertex 提供方）中取代 `gemini-3.6-flash`；3.6 代模型仍保持路由与支持。
- 客户端现在会往返传递线路上的函数调用 id：`tool_call` 将 `function_call.id` 存为自身的 `tool_call_id`（当 API 未下发时回退为函数名），重放的 `FunctionCall` 会把该 id 带回，并且每个 `FunctionResponse` 都同时包含调用 id 和函数名，正如 generateContent API 所要求的那样。函数名从对话中更早的匹配 `tool_call` 还原；在开始存储 id 之前产生的历史记录会把函数名作为其 `tool_call_id`，并降级为此前仅含函数名的形式。较旧的 `gemini3` 客户端仍只发送仅含函数名的响应，本次未作改动。

## 注册表元数据

`gemini-3.7-flash` 的注册信息为：文本、图像、视频和音频输入，文本输出，1,048,576 token 的上下文窗口，以及官方标价每百万 token 输入 $1.50、输出 $7.50（思考按输出计费）、上下文缓存读取 $0.15 —— 与 `gemini-3.6-flash` 的标价相同。Google 以上线折扣的形式将这三项费率减半，有效期至 2026-12-31，而注册表的固定定价并未对此建模。
