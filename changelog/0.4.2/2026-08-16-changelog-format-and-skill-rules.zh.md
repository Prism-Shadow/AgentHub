# 结构化的更新日志条目，以及两条开发 skill 规则

- **Date:** 2026-08-16
- **Type:** process
- **Scope:** `changelog`, `skills`
- **PR:** [#170](https://github.com/Prism-Shadow/agenthub/pull/170)

[English](2026-08-16-changelog-format-and-skill-rules.md)

## 变更内容

- 现在每个更新日志详情文件都以一个元数据块开头——`Date`、`Type`、`Scope`、`PR`、`Issue`、`Breaking`——紧接标题之下，并保持这一固定顺序，使读者和 `grep` 都能在同一位置找到每个字段。已迁移全部 27 个现有条目，并且每个发布版本 README 中的行现在都会在详情链接旁附带其 PR 链接。
- 条目正文中裸写的 `(#N)` 引用改成了真正的链接。裸写的 `#N` 在 Markdown 文件中会渲染为纯文本（GitHub 只在 issue 与 PR 评论中为其自动生成链接），因此这些引用对读者和 agent 而言都无法当作链接使用。
- 未发布的内容被钉在同一个目录里：README 标题带 `(unreleased)` 标记的那个唯一发布版本目录，用 `grep -l '(unreleased)' changelog/*/README.md` 即可找到。任何情况下都不得为尚未发布的工作另开目录，也不得自行臆测下一个版本号。
- `changelog/README.md` 记录了该格式：可供复制的模板、定义每个字段的表格、正文规则，以及回答常见问题的 grep 配方（“哪些变更曾破坏兼容性？”、“所有涉及某个客户端的条目”）。
- 现在本目录树下每个文件都有两种语言——`<name>.md` 与 `<name>.zh.md`，逐节互相对应：28 个详情条目、8 个发布版本 README、根目录 `CHANGELOG.md`，以及约定文档本身。每个文件都在元数据块正下方链接到它的对应版本。
- `agenthub-dev` skill 新增了两条规则。阶段 2：当抓取到的交互中有部分内容无法序列化为 JSON 时，保存其 `str()` 形式并据此分析——用一个 JSON 对象包裹，使 `.jsonl` 仍可解析——而不是丢弃该事件、手工把它改写成合法 JSON，或退回去依赖文档。阶段 4：`AVAILABLE_MODELS` 条目是新模型唯一有权做出的测试改动——共享的 e2e 测试套件是每个客户端本就必须满足的契约，任何范围更大的修改都需要逐次获得明确批准。

## 原因

- 这些条目本来就包含了正确的信息，只是形态不便于查找：PR 归属即便存在也埋在正文里，而正文之上没有任何内容说明该条目属于哪类变更、触及了哪些模块。一个 agent 要回答“`temperature` 是从什么时候起不再被接受的，由哪个 PR 完成？”，就必须把条目从头读到尾。元数据块把这变成了一次 `grep`，并让答案紧挨着人类可读的记录，而不是放进一个会逐渐失真的独立索引。
- 最初选择的是朴素的 `Key: value` 行，沿用启发了本方案的 [deepseek-harness agent notes](https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/notes/README.md) 格式，但连续的行在渲染时会挤成一个连排的段落。项目符号列表能正确渲染，仍可按字段名 grep，并且在原始文本形态下读起来也一样。
- 可选字段是直接省略而不是填入占位符，正是这一点使 `grep -rl 'Breaking:' changelog/` 成为查询破坏性变更的精确查询。
- 最早的两个条目（0.2.0）没有 PR 链接：它们早于这一约定，并且被 [#162](https://github.com/Prism-Shadow/agenthub/pull/162) 整体重新分组，因此不靠猜测就无法把某个具体的 PR 归属给它们。同样地，`Breaking: yes` 也只在条目本身记录了破坏的情况下才写——在若干次模型刷新中被重命名的客户端类从未从 `__init__.py` 导出，因此那些重命名没有破坏任何用户代码。
- 翻译元数据块会把每条查询一分为二。字段名、`Type` 取值、`Scope` 标识符、日期与链接一律原样保留英文，因此无论文件是哪种语言，`grep -rl 'Breaking:' changelog/` 返回的仍是完整集合；只有散文和小节标题被翻译，而标准小节标题有固定译法（`## 变更内容`、`## 原因`、`## 兼容性`），同样保持可 grep。
- 章节结构只是一项建议，而非回溯改造：27 个条目中有 21 个是标题加一个项目符号列表，把它们的正文改写成固定的章节方案只会无谓地扰动历史记录。它们只加了一个 `## What changed` 标题，此外没有任何改动。
