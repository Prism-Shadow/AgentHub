# MiniMax M3 支持

- **Date:** 2026-08-03
- **Type:** feature
- **Scope:** `minimax_m3`, `auto_client`, `registry`, `tests`
- **PR:** [#167](https://github.com/Prism-Shadow/agenthub/pull/167)

[English](2026-08-03-minimax-m3.md)

AgentHub 现已支持位于 `https://api.minimax.io/v1` 的官方 MiniMax `MiniMax-M3` Responses API。`minimax-m3` 客户端通过 `MINIMAX_API_KEY` 接受 MiniMax Token Plan 订阅密钥或按量付费 API key；`MINIMAX_BASE_URL` 可覆盖默认端点。

## 协议实现

- 新增了配套的 Python 与 TypeScript MiniMax Responses 客户端、精确匹配 `MiniMax-M3` 的路由、一个受支持模型注册表条目、由环境变量开关控制的 E2E 注册，以及 CI 密钥透传。
- 构造时必须提供 `MINIMAX_API_KEY`（或显式的 `api_key`）。否则被封装的 OpenAI SDK 会回退到 `OPENAI_API_KEY`，把 OpenAI 的凭据发送到 MiniMax 主机。
- 自动路由仍然只匹配完全一致的 `MiniMax-M3` 模型 id，但客户端本身接受任意模型名称，因此显式指定 `client_type="minimax-m3"` 就能访问网关托管或使用别名的部署——这一点与其他所有客户端相同。
- 这两个客户端沿用了 GPT-5.5 客户端的流式结构：工具调用的名称与 `call_id` 从 `response.output_item.added` 中获取，其参数由 `response.function_call_arguments.delta` 累加，完整的 `tool_call` 在 `response.function_call_arguments.done` 时发出；`response.output_item.done` 被忽略。并行调用一个接一个流式返回，因此单个累加器即可承载。
- 任何地方都不记录 fidelity：reasoning item 仅由思考文本重建，文本 item 不带 phase，函数调用只携带 `call_id`、`name` 与重新序列化的 `arguments`。`call_id` 存放在通用的 `tool_call_id` 字段上，回放的 `function_call` 与 `function_call_output` item 都需要它。
- `finish_reason` 由 `response.status` 映射而来：`completed` → `stop`，`incomplete` → `length`，其他一律 → `unknown`。截断通过 `response.incomplete` 终止事件体现，该事件的 usage 中没有 `output_tokens_details`，因此两个 usage 明细块在缺失时都默认为零；完全不上报 usage 的响应不会产生任何 usage 元数据，而不是编造零值，由基础客户端的末事件校验来负责处理。
- `response.failed` 与流式错误事件没有专门的转换；它们与 GPT-5.5 客户端一样，通过未知事件保护分支体现。
- 抓取到的推理使用 `response.reasoning_text.delta`，而不是 OpenAI 的 reasoning-summary 事件。MiniMax 不使用 OpenAI 的加密推理内容，因此 AgentHub 也不请求它。
- 已完成响应的 usage 将 `input_tokens_details.cached_tokens` 映射为 `cached_tokens`，将 `output_tokens_details.reasoning_tokens` 映射为 `thoughts_tokens`。

## 配置行为

| AgentHub 配置 | MiniMax 请求行为 |
| --- | --- |
| `system_prompt` | `instructions` |
| `max_tokens` | `max_output_tokens` |
| `temperature` | 在文档规定的 0–1 范围内直接透传；其他取值抛出 `UnsupportedParameterError`。 |
| `ThinkingLevel.NONE` | `reasoning.effort = "none"`。 |
| `ThinkingLevel.LOW` / `MEDIUM` / `HIGH` | `reasoning.effort` 为 `low` / `medium` / `high`。 |
| `ThinkingLevel.XHIGH` | 优雅降级为 `high`。 |
| `thinking_summary` | 省略，因为 MiniMax 未在文档中给出对应的请求字段。 |
| `PromptCaching.ENABLE` | 省略；MiniMax 的缓存是自动的。 |
| `PromptCaching.DISABLE` | 抛出 `UnsupportedParameterError`；MiniMax 未在文档中给出禁用缓存的设置。 |
| `PromptCaching.ENHANCE` | 抛出 `UnsupportedParameterError`；MiniMax 未在文档中给出可配置的缓存保留设置。 |
| `tool_choice` 为 `auto` / `none` | 直接透传。 |
| `tool_choice` 为 `required` 或具名工具列表 | 抛出 `UnsupportedParameterError`；MiniMax 未在文档中给出这些模式。 |

## 注册表元数据

`MiniMax-M3` 的注册信息为：输入支持文本与图像，输出为文本，上下文窗口 1,000,000 token，并采用 ≤512K 输入档位的官方标价：每百万 token 输入 $0.30、输出 $1.20（推理按输出计费）、缓存读取 $0.06。当输入超过 512K token 时，MiniMax 会把这三项费率全部翻倍，而注册表的扁平定价无法表达这一点，因此声明的是基础档位。
