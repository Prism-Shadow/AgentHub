# UniConfig 的 fast mode

- **Date:** 2026-08-17
- **Type:** feature
- **Scope:** `types`, `openai_chat`, `openai_responses`, `ant_messages`, `claude5`
- **PR:** [#171](https://github.com/Prism-Shadow/agenthub/pull/171)

[English](2026-08-17-fast-mode.md)

## 变更内容

- `UniConfig` 新增 `fast_mode: bool`，用于溢价的快速推理档位。
- OpenAI 协议 client（`openai_chat`、`openai_responses`、`gpt5_6`、`minimax_m3`）将其映射为
  `service_tier: "priority"`；Anthropic 协议 client（`ant_messages`、`claude5`）映射为
  `speed: "fast"` 并附带 `fast-mode-2026-02-01` beta 请求头。
- 没有 fast 档位的 client（`gemini3_7`、`glm5_3`、`kimi_k3`、`deepseek_v4`、
  `openai_embedding`，以及 Claude 4.6 模型或 Bedrock 上的 `claude5`）在设置
  `fast_mode` 时抛 `UnsupportedParameterError`。

## 配置行为

- 实测验证：OpenAI、OpenRouter 与 MiniMax 按 `service_tier: "priority"` 处理请求并在响应中
  回显该档位；DeepSeek 与 Z.AI 忽略该参数，按 standard 档位处理。
- Anthropic fast mode 是限 Claude Opus 5 与 Claude Opus 4.8 的 research preview：请求链路
  可通过校验，未获授权的组织会收到 429（"rate limit of 0 fast mode input tokens per
  minute"），直至 Anthropic 开通权限。第三方 Anthropic 兼容服务端忽略 `speed` 与 beta
  请求头。
- MiniMax 的 `priority` 按 standard 的 1.5 倍计价；OpenAI 与 Anthropic 的 fast 档位有各自
  的溢价价目。
