# GLM-5.3 支持与统一的 GLM 客户端

- **Date:** 2026-08-14
- **Type:** feature
- **Scope:** `glm5_3`, `glm5_1`, `glm5_2`, `auto_client`, `registry`
- **PR:** [#169](https://github.com/Prism-Shadow/agenthub/pull/169)

[English](2026-08-14-glm-5.3.md)

AgentHub 现已支持 Z.AI/智谱的 `glm-5.3`（发布公告见 https://z.ai/blog/glm-5.3），并且 GLM 系列客户端参照 Gemini 的统一做法合并为一个：`glm5_1/` 和 `glm5_2/` 在每种语言中并入单一的 `glm5_3/` 客户端，以最新一代命名。除思考参数契约外，5.1 与 5.2 的实现仅在 `reasoning_effort` 映射上有所不同，因此各代的规则现在集中于一个客户端中。

## 实现说明

- **仅依据文档的实现。** 本次变更时 GLM-5.3 API 已公布但尚未上线，因此不存在实况抓取；该实现依据 docs.bigmodel.cn 上的官方预上线文档，快照存放于 `llmsdk_docs/glm5_3/`。在 API 上线之前，E2E 模型仍保持 `glm-5.2`。
- 按文档所述，GLM-5.3 保持 GLM-5.2 的线路格式（1M 上下文、128K 最大输出，流式 `reasoning_content`/`content`/`tool_calls`、`tool_stream`、`tool_choice` 仅支持 `auto`），仅改变思考契约：
  - GLM-5.3 采用强制思考，且**在 `thinking.type: "disabled"` 上报错**，因此 `ThinkingLevel.NONE` 降级为新的轻量推理 `low` 档位并保持思考启用。
  - GLM-5.3 的 `reasoning_effort` **只接受 `low`/`high`/`max`**，其他取值会报错，因此客户端进行钳制：`LOW` → `low`，`MEDIUM`/`HIGH` → `high`，`XHIGH` → `max`。GLM-5.2 保留完整的透传词表（由服务端负责映射），5.2 之前的模型则完全不发送 `reasoning_effort`。
- 路由收敛到 `glm-5` 前缀，此前接受的每个 GLM 客户端类型都包含该前缀，因此 `glm-5.1`/`glm-5.2` 的写法仍可继续使用；支持类型的提示信息将 `glm-5.3` 列在首位。官方注册表条目改为指向 `glm-5.3`；OpenRouter 托管的 `z-ai/glm-5.2` 条目未作改动。

## 注册表元数据

`glm-5.3` 的注册信息为：文本输入/输出，以及 1,000,000 token 的上下文窗口。定价从略：该 API 尚未上线，且 Z.AI 在快照时未公布 GLM-5.3 的价格。
