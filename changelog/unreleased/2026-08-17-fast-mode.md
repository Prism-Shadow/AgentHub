# Fast mode in UniConfig

- **Date:** 2026-08-17
- **Type:** feature
- **Scope:** `types`, `openai_chat`, `openai_responses`, `ant_messages`, `claude5`
- **PR:** [#171](https://github.com/Prism-Shadow/agenthub/pull/171)

[中文版](2026-08-17-fast-mode.zh.md)

## What changed

- `UniConfig` gained `fast_mode: bool` for fast processing at premium pricing.
- OpenAI-protocol clients (`openai_chat`, `openai_responses`, `gpt5_6`, `minimax_m3`) map it
  to `service_tier: "priority"`; Anthropic-protocol clients (`ant_messages`, `claude5`) map
  it to `speed: "fast"` with the `fast-mode-2026-02-01` beta header.
- Clients without a fast tier (`gemini3_7`, `claude4_6`, `glm5_3`, `kimi_k3`, `kimi_k2_6`,
  `deepseek_v4`, `openai_embedding`, and `claude5` on Bedrock) raise
  `UnsupportedParameterError` when `fast_mode` is set.

## Configuration behavior

- Verified live: OpenAI, OpenRouter, and MiniMax serve `service_tier: "priority"` requests
  and echo the tier back; DeepSeek and Z.AI ignore the parameter and serve at standard tier.
- Anthropic fast mode is a research preview limited to Claude Opus 5 and Claude Opus 4.8:
  the request wiring passes validation, and organizations without access receive a 429
  ("rate limit of 0 fast mode input tokens per minute") until Anthropic grants it.
  Third-party Anthropic-compatible servers ignore `speed` and the beta header.
- MiniMax prices `priority` at 1.5x standard; OpenAI and Anthropic fast tiers carry their
  own premium price lists.
