# Support Gemini 3.8 Flash

- **Date:** 2026-09-03
- **Type:** feature
- **Scope:** `gemini3_8`, `registry`, `claude5`, `ant_messages`, `glm5_3`
- **PR:** [#199](https://github.com/Prism-Shadow/agenthub/pull/199)

[中文版](2026-09-03-gemini-3.8-flash.zh.md)

## What changed

- AgentHub supports `gemini-3.8-flash` on the official Gemini API and Vertex AI: text, image,
  video and audio in, text out, a 1,048,576-token context window, 65,536 output tokens.
- The wire contract is identical to the 3.7 generation, so the shared client folder is renamed
  for the newest generation as usual: `gemini3_7/` becomes `gemini3_8/` and `Gemini3_7Client`
  becomes `Gemini3_8Client` in both languages. Every Gemini registry row — text, image, TTS and
  embedding — now names `gemini-3.8` as its client.
- Routing is unchanged: the branch still matches on the `gemini-3` prefix, so `gemini-3.7`,
  `gemini-3.6` and `gemini-3` remain accepted `client_type` spellings and reach the renamed
  client. A test pins that.
- The 3.8 generation rejects `minimal` thinking with a 400 the way 3.7 does, so it joins that
  branch: `thinking_level: none` clamps to `low` rather than being forwarded.
- `gemini-3.8-flash` replaces `gemini-3.7-flash` in the env-gated E2E model lists, official and
  Vertex.
- `llmsdk_docs/gemini3_8/` snapshots the generation overview, the model spec and the thinking
  table; the 3.7, 3.6 and 3 thinking tables gain the new model, and the docs index lists it.

## Pricing

- `gemini-3.8-flash` was registered at Google's list price — $1.50 input, $7.50 output and
  $0.15 cached input per million tokens — the same table `gemini-3.7-flash` and
  `gemini-3.6-flash` already carried.
- Google's launch discount through 2026-12-31 halves all three rates on all three models and
  was deliberately left unrecorded: the registry's job is the catalog price, and applying a
  running promotion is the consumer's. The comment on the new row says so.

## Configuration behavior

- `thinking_summary` stopped depending on `thinking_level`. It had sat inside the level
  branch in `claude5`, `ant_messages`, `deepseek_v4` and `gpt5_6`, so a summary asked for on
  its own never reached the request, and `deepseek_v4` dropped it whatever else was passed.
  Each of those clients now sends the switch on its own: `thinking.display` for the
  Anthropic protocol, `reasoning.summary` for the Responses protocol.
- `thinking_summary: false` reaches the Anthropic-protocol clients as
  `thinking.display: "omitted"` rather than being read as unset, matching the
  `include_thoughts=False` the Gemini client already sent.
- GLM generations before 5.2 receive the clamped `reasoning_effort` instead of having it
  dropped in the client; Z.AI, OpenRouter and SiliconFlow all accept the parameter there.
- Three places keep their existing behaviour because the vendor answers the alternative with
  a 400: the Gemini 2.5 series rejects every `thinking_level` value, so the parameter stays
  omitted for it (`include_thoughts` still rides along); the Anthropic Messages API rejects
  `display` on the disabled thinking block that `thinking_level: none` selects there; and
  `openai_responses` keeps its summary tied to a level, because OpenRouter reads an
  effort-less `reasoning` object as "reasoning disabled" and refuses it on a forced-thinking
  model.
