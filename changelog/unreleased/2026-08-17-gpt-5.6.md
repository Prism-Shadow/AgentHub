# GPT-5.6 support

- **Date:** 2026-08-17
- **Type:** feature
- **Scope:** `gpt5_6`, `auto_client`, `registry`, `tests`
- **PR:** [#171](https://github.com/Prism-Shadow/agenthub/pull/171)
- **Breaking:** yes — the `gpt5_5` client folder was renamed to `gpt5_6` and its class `GPT5_5Client` to `GPT5_6Client`; deep imports of the old path stop working.

[中文版](2026-08-17-gpt-5.6.zh.md)

## What changed

- The official GPT-5.6 generation (`gpt-5.6` alias plus `gpt-5.6-sol`/`gpt-5.6-terra`/
  `gpt-5.6-luna`) is supported. Live captures confirmed the wire protocol is identical to
  GPT-5.5 — reasoning summaries via `response.reasoning_summary_text.delta`, reasoning items
  with `encrypted_content` (emitted by default under `store: false`), `phase` on assistant
  messages, and the `summary` key required on replayed reasoning items — so the `gpt5_5`
  client folder was renamed to `gpt5_6` (`GPT5_6Client`) and now routes `gpt-5.4`, `gpt-5.5`,
  and `gpt-5.6` client types.
- `llmsdk_docs/gpt5_6/` snapshots the GPT-5.6 guides (model variants, `max` reasoning effort,
  `reasoning.mode: "pro"`, `reasoning.context`, fast mode); the GPT-5.5 snapshot stays in
  `llmsdk_docs/gpt5_5/`.
- The official e2e entry moved from `gpt-5.5` to `gpt-5.6-luna`. `gpt-5.6` (sol) answered the
  image-in-tool-result flow with an empty final message in roughly half of raw-SDK trials
  (URL and base64 alike, reproduced outside AgentHub), while `gpt-5.6-luna` answered 5/5, so
  the stable variant carries the e2e coverage.

  ($2/$12, cached $0.2), `gpt-5.6-luna` ($0.2/$1.2, cached $0.02), all 1,050,000-token
